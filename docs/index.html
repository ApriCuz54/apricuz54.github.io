Research & Publications

Cost-Aware Fine-Tuning for Efficient LLM Adaptation

First Author | IEEE AIMLSys EDGE-X 2025 (Accepted) | Jan 2025 - June 2025

BITS Pilani, Goa Campus

Research Overview

Conducted a comprehensive system-level study addressing one of the most pressing challenges in production LLM deployment: balancing model performance with computational and financial costs. This research provides practitioners with actionable, hardware-specific recommendations for efficient fine-tuning across diverse computational environments.

Key Findings & Impact

  • Identified a dominant fine-tuning strategy: Freezing all but the top two transformer layers achieves perfect accuracy (100%) matching full fine-tuning while training only 9% of parameters and reducing CPU training time by up to 86%
  • Multi-hardware benchmark: Evaluated PEFT methods (LoRA, layer freezing) across CPU, T4, L4, and A100 GPUs, providing the first comprehensive cost-performance analysis across this hardware spectrum
  • Hyperparameter optimization efficiency: Demonstrated that Random Search reduces tuning time by 30% with only marginal performance trade-offs compared to Grid Search
  • Financial cost analysis: Quantified real-world cloud deployment costs and introduced "Loss Reduction per Dollar" metric, showing CPU-based freeze strategies deliver 3x better value than GPU alternatives for budget-constrained scenarios
  • Production-ready recommendations: Delivered hardware-specific blueprints enabling practitioners to select optimal configurations based on their primary constraint (speed, budget, or balanced approach)

Technical Contributions

  • Benchmarked modern PEFT techniques including LoRA (ranks 4 and 8), BitFit-style approaches, and layer-freezing strategies across multiple model architectures (DistilBERT, BERT, LLaMA-3.2-1B)
  • Designed multi-stage experimental methodology combining hyperparameter optimization analysis with system-level PEFT benchmarking
  • Collected fine-grained system metrics: peak GPU memory utilization, real-time GPU usage percentages, gradient norms, and end-to-end training latency
  • Conducted experiments on diverse NLP tasks: sentiment classification (IMDb, 5K samples) and instruction-following (Alpaca dataset)

Real-World Impact

This research directly addresses the prohibitive costs of LLM fine-tuning in pay-per-use cloud environments. By demonstrating that simple layer-freezing strategies can match full fine-tuning performance while dramatically reducing computational requirements, this work makes powerful AI more accessible to:

  • Startups and small teams with limited GPU budgets who can achieve production-quality results on CPUs
  • Enterprise ML teams seeking to optimize cloud spending without sacrificing model quality
  • Academic researchers who need cost-effective experimentation strategies
  • Edge AI applications requiring efficient on-device model adaptation

Frameworks: PyTorch, Hugging Face Transformers, LLaMA-Factory, Unsloth

During my internship at AMD, I worked on optimizing large language models (LLMs) to run efficiently on Neural Processing Units (NPUs), with a specific focus on ensuring compatibility with AMD's RyzenAI chips. My team's primary focus was enabling Copilot+ on Windows machines globally. This task required an in-depth understanding of LLM architecture and familiarity with machine learning frameworks like ONNX and ONNXRuntime.

To meet the goals, I developed a production-level package designed to optimize LLMs by pre-processing model layers and formatting data for efficient NPU deployment. This package, which was sent to customers, delivered up to a 300% improvement in model initialization speed on NPUs. In addition to building the package, I developed a comprehensive set of testing tools to ensure these optimizations were stable across different NPU configurations, preventing performance regressions. I also implemented a graph comparison script using graph isomorphism techniques, which expedited the process of checking compatibility with frequently updated LLM versions. This script saved the team approximately five man-hours each week and streamlined the deployment process, ensuring that AMD's global Copilot+ deployment remained robust and performant.
